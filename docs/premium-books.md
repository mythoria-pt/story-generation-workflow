# Premium illustrated books

The story workflow resolves the saved book type after claiming the run. Premium work requires a matching accepted request, author, eligible audience and queued revision. The Web App checks the experimental preference when accepting the request. The worker resumes accepted work from the same run and frozen inputs. The Pub/Sub book type, when present, must agree with the story marker.

## Configuration

Set `PREMIUM_BOOK_BUCKET` to the dedicated private bucket shared with the Web App. Use uniform bucket-level access and enforce public access prevention. The SGW service account needs to read the bucket configuration and IAM policy and to create, read and remove its own objects. The Web App needs to read objects by storage generation. Keep older published objects available for pinned paid print orders. The SGW service account also needs permission to launch and inspect the existing `mythoria-story-generation` workflow for operator recovery.

| `PREMIUM_IMAGE_PROVIDER`    | `openai`                 |
| `PREMIUM_IMAGE_MODEL`       | `gpt-image-2.6-sunburst` |
| `PREMIUM_IMAGE_QUALITY`     | `high`                   |
| `PREMIUM_IMAGE_SPREAD_SIZE` | `3840x1952`              |
| `PREMIUM_IMAGE_SQUARE_SIZE` | `1536x1536`              |

The text provider uses the configured story text model for the storyboard and a visual review of each generated illustration. Premium image usage records the measured provider input and output tokens and the stage latency. Story content and references stay out of these records. Sunburst price estimation uses reported text and image token counts at the published rates. The account invoice remains the record of actual billing. ## Book and storage contract

The [storyboard prompt and editorial guidance](premium-storyboard-prompt.md) explain how the generator selects text placement and show examples from both age groups.

New storyboards select `openingDesign.motif` and `openingDesign.background` once. The published manifest freezes both. Keep the opening-design registry in sync with the Web App and preserve existing motif paths and colours for previously published books. The title and dedication use the selected line drawing, and all four opening pages use the selected pastel. Historical checkpoints and manifests without this field retain their original design.

New 33-page books also request one small transparent ornament based on a recurring object and the spread that shows it. The publisher pins an accepted PNG as `motifArtwork` and uses those same bytes on pages 1 and 3. Missing or rejected output uses the selected curated drawing. A durable attempt receipt prevents a duplicate provider call if the workflow loses the response. A concurrent publisher retries while an active attempt is choosing the ornament.

- `stories.features.premiumBook` holds `version: 1`, `type: premium_children` and state `draft`, `queued` or `published`. Queued and published markers carry the revision UUID, owner and eligible audience. The initial revision is the accepted workflow run ID. A published marker also carries the manifest key, storage generation, SHA-256 and byte count.
- `{storyId}/premium/revisions/{revision}/manifest.json` records the immutable edition. Its assets live in story-scoped revision directories with content-addressed names. Pages 1–4 contain the localized opening information and dedication, page 5 is the opener, pages 6–31 form thirteen facing spreads and page 32 is the narrative ending.
- Newly frozen inputs and their published manifests use `editionLayout: "embedded-lettering-v2"`. These editions have 33 interior pages. The opener, facing spreads and ending carry approved lettering in the illustrations. Each narrated page keeps its exact canonical text for accessibility and corrections. The print exporter uses the same artwork without a narrative overlay. Page 2 uses the localized `classic-v2` technical page with selectable PDF text, the Mythoria logo and QR. The hardcover casewrap keeps the separate title and synopsis.
- Page 33 contains the localized publisher invitation. Its text and link to the localized Mythoria story creator are frozen with the accepted input. Older inputs and manifests without `editionLayout` keep their existing 32- or 33-page plan and text overlays, including after a spread correction. A paid order still renders the edition pinned at purchase.
- Each spread can use `both_pages` or `right_only`. An omitted layout means `both_pages`. Ages 0–2 favour a brief spoken phrase and repetition. Ages 3–6 can use both pages for a short sequence or dialogue and a silent left page for a reveal. The storyboard adapts phrasing to the book's language and the space available at the normal type size. A silent left page has both artwork derivatives and an empty canonical text field.
- An embedded-lettering spread uses one panorama to guide the composition of two separately rendered 2672 × 2672 pixel pages. The panorama shows one drawable instant with each recurring character appearing once, allowing a natural reflection in the same setting. An independent guide review checks visual continuity and the gutter before page rendering starts. It stores approval against the verified guide digest. A rejection supplies a concrete alternative staging for the next attempt, keeping the original narration and required visual clue. The rendered pages join in the binding overlap. The exporter compares the dimensions of the provider output with the full-bleed print geometry. Native pages use a 304-PPI grid and retain their original scale apart from cropping and the overlap blend. The standalone opener, ending and cover art also use native 2672 × 2672 pixel inputs.
- An independent visual reviewer transcribes the final trimmed pages from their images. The worker compares each transcription with the pinned narration, preserving spelling, accents, capitalisation and punctuation. The same review checks reading size, contrast, childlike lettering and illustration, trim, gutter and visual continuity. Reusable private checkpoints pin the panorama and each successful tile. A lettering failure with a known page replaces only that tile. Uncertain locations or illustration failures call for both tiles, and a structural rejection can replace the shared guide. A temporary provider failure can resume from the last successful checkpoint.
- Preexisting panel editions use the placement reference and text boxes from the frozen legacy plan. The visual review checks whether the trim, gutter or typeset panel covers an essential detail. A sole upper-panel obstruction receives one lower-panel review. A visual rejection can preserve a compact edit draft and check names in the same revision for a subsequent attempt. Approved legacy artwork records its selected boxes.
- Digital captures use a common 96-PPI grid and lossless PNG. The two trims rejoin without additional resampling. Print captures use a 304-PPI grid with 38 bleed pixels on each edge. Adjacent pages overlap by 76 pixels in the bleed and meet at the centre of the visible trim. The private manifest retains native dimensions and effective PPI separately from the export grid.
- Ebook publication screenshots the opening pages and publisher invitation directly from their HTML in Chromium. The 816 × 816 PNGs use the same 96-PPI trim as the illustrated reading pages, and the manifest pins them in `pages[].reading`. The reader keeps the publication details and invitation as HTML. Earlier manifests can omit these previews. A correction preserves existing previews and generates any missing ones before publication. The ebook job creates no PDFs. See [premium self-print](print.md#premium-square-self-print) for the separate on-demand export.
- A completed stage writes an immutable checkpoint. A per-stage storage lease prevents duplicate provider work during overlapping retries, and a later execution can recover an expired lease. Each checkpoint binds to the frozen input and configured models. Publication verifies the full asset set before changing the story pointer with a row lock and expected revision.

## Local embedded-lettering design preview

For a design review, start with a completed spread's pinned text and art reference and generate one panoramic PNG containing the exact left and right passages. Keep the candidate in a private local directory. Build the specification page from the book's localized metadata using HTML typography, with the packaged logo and QR as images. Preserve this page's live text in the reader and copy its single-page PDF directly into the excerpt so its text and fonts survive export.

From the SGW checkout, run `npx tsx scripts/preview-lettered-spread.ts <panorama.png> <existing-preview-directory> <spec.pdf>`. The command uses the production spread crops, writes `left.png` and `right.png` for the reader, and creates a three-page `excerpt.pdf`. Without the final argument it creates a two-page `spread.pdf`. Use a dedicated output directory because these local output names are reused. Check both final page images against the pinned text, including accents and punctuation. The command reports the native effective PPI so an operator can assess lettering at print size.

For a complete local proof, run `npx tsx scripts/render-premium-edition.ts <manifest.json> <asset-dir> <new-output-dir> <specification-qr.png>`. Place local copies of cover and page artwork and any opening motif in the asset directory using their content-addressed file names. The command checks each file against its manifest digest and byte count, then uses the paid-proof renderer to write `interior.pdf` and `cover.pdf`. Supply a local copy of the print QR asset. The usual Chromium, Poppler and sRGB profile dependencies apply. PDF quality issues are reported in the command output and set a nonzero exit status.

## Operator recovery and correction

Call `POST /internal/premium/runs/{runId}/resume` with `{ "storyId": "…" }` through authenticated SGW access. It resumes an eligible failed or blocked run, or a run whose recorded Workflows execution has failed. Active work returns its current run identity. Concurrent retry calls converge at the workflow claim, which checks the same prior status and update timestamp. The original acceptance, debit, revision and validated checkpoints are retained.

Call `POST /internal/premium/stories/{storyId}/corrections` with the current `expectedRevision`, a new UUID `correctionId` and one `spreadId` (such as `spread-3`). Provide `leftText`, `rightText` or `artworkInstructions` as needed. To switch a pair to `right_only`, explicitly provide that layout, empty `leftText` and the new `rightText`. To restore `both_pages`, provide the new left line. A change to embedded text generates and verifies a replacement spread in the same layout. For older editions with text overlays, text-only corrections reuse the existing artwork. Artwork corrections generate and verify a new master and both derivatives. The request may be retried with the same body and correction ID. A stale expected revision must be reviewed before another attempt. The returned revision includes `previousRevision` in its manifest so staff can explicitly rebind a held paid order through the existing revise-proof workflow.

### Draft retention

After a premium run reaches `completed` or `cancelled`, the worker makes a best-effort pass over the run's `review/` objects. It checks execution identity again after listing and deletes only the exact generations of matching `.draft.jpg` objects. This cleanup uses existing bucket permissions to list and delete objects. Failed and blocked runs retain their drafts for same-run recovery. Published assets, paid-order pins and stage checkpoints remain available.

As a bucket backstop, use a seven-day Cloud Storage lifecycle delete rule with `age: 7` and `matchesSuffix: [".draft.jpg"]` on the dedicated premium bucket. Cloud Storage takes a literal suffix. This rule covers drafts left by interrupted runs, abandoned corrections and transient cleanup failures. Same-run recovery can generate fresh artwork if its draft has expired. Existing soft-delete and versioning policies still apply. [Cloud Storage lifecycle conditions](https://docs.cloud.google.com/storage/docs/lifecycle#lifecycle_conditions)

## Online editions and owner edits

Generation publishes the digital edition without creating PDFs. WebApp calls the authenticated premium corrections prepare endpoint to stage an illustration change, then applies the pinned manifest and records any image-edit debit in one database transaction. The existing staff corrections endpoint can publish directly. The premium copy endpoint gives each owner duplicate its own story and immutable image paths. Only self-print and physical proof requests enter the PDF renderer.

# Premium illustrated books

The story workflow resolves the saved book type after claiming the run. Premium work requires a matching accepted request, author, eligible audience and queued revision. The Web App checks the experimental preference when accepting the request. The worker resumes accepted work from the same run and frozen inputs. The Pub/Sub book type, when present, must agree with the story marker.

## Production release

On 25 November 2026, Cloud Run revision `story-generation-workflow-git-e25e193592d8-premium` served 100% of traffic in `europe-west9`. Production workflows were `mythoria-story-generation` revision `000122-258`, `print-generation` revision `000045-6f1` and `audiobook-generation` revision `000051-1ee`. This release covers generation and recovery of the embedded-lettering edition, spread corrections, [square self-print](print.md#premium-square-self-print), [physical proofs](print.md#premium-square-proof-files) and [single-file premium audiobooks](audio-narration-system.md#premium-illustrated-editions).

## Configuration

Set `PREMIUM_BOOK_BUCKET` to the dedicated private bucket shared with the Web App. Use uniform bucket-level access and enforce public access prevention. The SGW service account needs to read the bucket configuration and IAM policy and to create, read and remove its own objects. The Web App needs to read objects by storage generation. Keep older published objects available for pinned paid print orders. The SGW service account also needs permission to launch and inspect the existing `mythoria-story-generation` workflow for operator recovery.

| Variable                    | Default                  |
| --------------------------- | ------------------------ |
| `PREMIUM_IMAGE_PROVIDER`    | `openai`                 |
| `PREMIUM_IMAGE_MODEL`       | `gpt-image-2.6-sunburst` |
| `PREMIUM_IMAGE_QUALITY`     | `max`                    |
| `PREMIUM_IMAGE_SPREAD_SIZE` | `3840x1952`              |
| `PREMIUM_IMAGE_SQUARE_SIZE` | `1536x1536`              |
| `PREMIUM_TEXT_MODEL`        | `gemini-4-neon`          |

New premium storyboards, text fit repairs and visual reviews use Gemini 4 Neon by default. Set `PREMIUM_TEXT_MODEL=gemini-4-hydrogen` to choose Hydrogen for new premium runs. The standard pipeline uses `GOOGLE_GENAI_MODEL` independently. The premium image adapter uses OpenAI. Set `PREMIUM_IMAGE_QUALITY=low` in `.env.local` for low-quality local testing. Cloud Build deploys Neon and max quality by default through its `_PREMIUM_TEXT_MODEL` and `_PREMIUM_IMAGE_QUALITY` substitutions. Frozen runs keep their recorded models and quality. The configured spread size is the panorama size. The configured square size applies to inputs such as the character sheet and legacy square artwork. Embedded-lettering narrative pages and covers request a separate native size of 2672 × 2672 pixels. Usage records store measured provider tokens and image-stage latency. Private story content and references stay out of the records. Price estimates use published token rates and the invoice records actual billing. [Gemini model pricing](https://aistudio.google.com/docs/models/gemini-4-neon#pricing) · [OpenAI model pricing](https://developers.openai.com/api/docs/models/gpt-image-2.6-sunburst)

## Book and storage contract

The [storyboard prompt and editorial guidance](premium-storyboard-prompt.md) explain how the generator selects text placement and show examples from both age groups.

New storyboards select `openingDesign.motif` and `openingDesign.background` once. The published manifest freezes both. Keep the opening-design registry in sync with the Web App and preserve existing motif paths and colours for previously published books. The title and dedication use the selected line drawing, and all four opening pages use the selected pastel. Historical checkpoints and manifests without this field retain their original design.

New 33-page books also request one small transparent ornament based on a recurring object and the spread that shows it. The publisher pins an accepted PNG as `motifArtwork` and uses those same bytes on pages 1 and 3. Missing or rejected output uses the selected curated drawing. A durable attempt receipt prevents a duplicate provider call if the workflow loses the response. A concurrent publisher retries while an active attempt is choosing the ornament.

- `stories.features.premiumBook` holds `version: 1`, `type: premium_children` and state `draft`, `queued` or `published`. Queued and published markers carry the revision UUID, owner and eligible audience. The initial revision is the accepted workflow run ID. A published marker also carries the manifest key, storage generation, SHA-256 and byte count.
- `{storyId}/premium/revisions/{revision}/manifest.json` records the immutable edition. Its assets live in story-scoped revision directories with content-addressed names. Pages 1–4 contain the localized opening information and dedication, page 5 is the opener, pages 6–31 form thirteen facing spreads and page 32 is the narrative ending.
- Newly frozen inputs and published manifests use `editionLayout: "embedded-lettering-v2"`, `spreadLayoutVersion: 1` and `generationDesignVersion: 1`. These editions have 33 interior pages. The opener, narrated illustrated pages and ending carry approved lettering in the illustrations. The exact canonical text stays available for accessibility and corrections. Separate typeset pages use selectable text. Page 2 uses the localized `classic-v2` technical page, with selectable PDF text, the Mythoria logo and QR. The front cover carries verified title lettering. The back-cover source is wordless and the published treatment uses a small publisher badge.
- Page 33 contains the localized publisher invitation. Its text and link to the localized Mythoria story creator are frozen with the accepted input. Older inputs and manifests without `editionLayout` keep their existing 32- or 33-page plan and text overlays, including after a spread correction. A paid order still renders the edition pinned at purchase.
- A mixed storyboard chooses between a panorama, paired illustrations and one illustration facing a typeset page. Ages 0–2 favour brief phrases and repetition. Narrated illustrated pages allow up to 110 characters. Dedicated typeset pages allow 420 characters and three short paragraphs. A silent illustrated page contains artwork, empty canonical text and an accessibility description. An omitted `textLayout` in a historical manifest means `both_pages`.
- A panoramic spread uses one panorama to guide the composition of two separately rendered 2672 × 2672 pixel pages. The panorama shows one drawable instant with each recurring character appearing once, allowing a natural reflection in the same setting. An independent guide review checks visual continuity and the gutter before page rendering starts. It stores approval against the verified guide digest. A rejection supplies a concrete alternative staging for the next attempt, keeping the original narration and required visual clue. The rendered pages join in the binding overlap. The exporter compares provider dimensions with the full-bleed print geometry. Native pages use a 304-PPI grid and retain their original scale apart from cropping and the overlap blend.
- An independent visual reviewer transcribes the final trimmed pages without the expected words. The worker normalizes Unicode and collapses whitespace to allow line wrapping, then requires an exact match to the pinned narration, including accents, capitalisation and punctuation. The same review checks reading size, contrast, childlike lettering and illustration, trim, gutter and visual continuity. Reusable private checkpoints pin the panorama and each successful tile. A lettering failure with a known page replaces only that tile. Uncertain locations or illustration failures call for both tiles, and a structural rejection can replace the shared guide. A temporary provider failure can resume from the last successful checkpoint.
- Preexisting panel editions use the placement reference and text boxes from the frozen legacy plan. The visual review checks whether the trim, gutter or typeset panel covers an essential detail. A sole upper-panel obstruction receives one lower-panel review. A visual rejection can preserve a compact edit draft and check names in the same revision for a subsequent attempt. Approved legacy artwork records its selected boxes.
- Digital captures use a common 96-PPI grid and lossless PNG. The two trims rejoin without additional resampling. Print captures use a 304-PPI grid with 38 bleed pixels on each edge. Adjacent pages overlap by 76 pixels in the bleed and meet at the centre of the visible trim. The private manifest retains native dimensions and effective PPI separately from the export grid.
- Ebook publication screenshots the opening pages and publisher invitation directly from their HTML in Chromium. The 816 × 816 PNGs use the same 96-PPI trim as the illustrated reading pages, and the manifest pins them in `pages[].reading`. The reader keeps the publication details and invitation as HTML. Earlier manifests can omit these previews. A correction preserves existing previews and generates any missing ones before publication. The ebook job creates no PDFs. See [premium self-print](print.md#premium-square-self-print) for the separate on-demand export.
- A completed stage writes an immutable checkpoint. A per-stage storage lease prevents duplicate provider work during overlapping retries, and a later execution can recover an expired lease. Each checkpoint binds to the frozen input and configured models. Publication verifies the full asset set before changing the story pointer with a row lock and expected revision.

## Generation order and provider inputs

The standard storyboard and chapter routes are separate from the premium workflow. The premium workflow uses the stage list associated with the frozen input. Current runs complete the storyboard, front cover, cast references, back cover, opener, facing spreads in page order, ending and publication. Historical runs complete cast references before the front cover.

| Stage             | Inputs and output                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Storyboard        | Gemini receives title, audience, locale, original outline and synopsis, selected direction, and cast descriptions. It produces the manuscript, compact cover and page briefs, spoiler-free synopsis, recurring cast and style guide, and opening design. No photos enter this call. A second pass sees only the proposed shared guide and removes any scene-specific details. Gemini can shorten any typeset passage that fails the printable-area check. |
| Front cover       | OpenAI receives the cover-specific brief, medium and likeness guide, the exact title, locale and available approved original photo references. It produces one full-bleed, native-resolution cover with the title in the artwork. Gemini independently transcribes the trimmed cover, checks readability and safe composition, then the worker compares the transcription with the frozen title.                                                          |
| Cast references   | OpenAI receives the style and likeness guide and approved character photos. Cover-only uploads stay out of this call. Gemini checks for a single neutral lineup with recognizable cast and rejects episodic locations, vehicles, props, decorative details and montage elements.                                                                                                                                                                          |
| Back cover        | OpenAI receives the back-cover brief, style and likeness guide and cast sheet. It produces wordless background art with quiet space in the lower-left safe area. Gemini checks for writing and room for the badge.                                                                                                                                                                                                                                        |
| Opener and ending | OpenAI receives the selected scene, canonical line, guide and cast reference. Gemini independently transcribes and checks the printed trim.                                                                                                                                                                                                                                                                                                               |
| Facing spreads    | The panorama guide receives the local spread scene and cast reference. Each panorama tile receives its matching crop and the exact text for that page. Independent illustrations receive their own page brief and cast reference. A dedicated typeset page uses its saved text without an artwork request. Gemini reviews the composition and transcribes each embedded line.                                                                             |
| Publication       | An optional transparent ornament receives one brief, the visual style and the finished spread selected for that object. It uses the frozen image quality in current runs and low in historical runs. Artwork and text previews are pinned in the private manifest before the story pointer advances.                                                                                                                                                      |

The shared visual guide carries medium, palette, shape language and stable likeness. Locations and episodic objects belong to their individual cover or page briefs. Wide compositions and independent pages preserve that scope in generation and visual review.

New freezes also record `artDirectionVersion: 1` in the input and published manifest. The storyboard checkpoint includes one explicit scene direction for each illustration. It names the visible cast, actor, action, exact target, essential props and framing. A panorama has a single direction and each independent illustration has its own. Dedicated text pages have no art direction. The visual reviewer checks these assignments, including cases where a character is represented only by a hand. A scene-specific item can follow its owner through the beats where it is visibly carried. Its identity, colour and location stay in those directions. Shared references are neutral character likenesses without props, settings, title lettering or cover composition.

For new directed runs, the final artwork reviewer sees a crop taken from the print geometry and estimates a lettering rectangle, including punctuation, accents and decorative title strokes. The worker checks those coordinates against a 12% inset from each trim edge and independently compares the transcription with the frozen manuscript. The panorama review also checks the complete silhouettes and essential objects against the fold. Rejected lettering rerenders the affected page. A panorama with an incorrect visible cast, action target or prop placement receives a new composition. Earlier frozen workflows retain their prior reviewer contracts and accepted checkpoints.

## Local embedded-lettering design preview

For a design review, start with a completed spread's pinned text and art reference and generate one panoramic PNG containing the exact left and right passages. Keep the candidate in a private local directory. Build the specification page from the book's localized metadata using HTML typography, with the packaged logo and QR as images. Preserve this page's live text in the reader and copy its single-page PDF directly into the excerpt so its text and fonts survive export.

From the SGW checkout, run `npx tsx scripts/preview-lettered-spread.ts <panorama.png> <existing-preview-directory> <spec.pdf>`. The command uses the production spread crops, writes `left.png` and `right.png` for the reader, and creates a three-page `excerpt.pdf`. Without the final argument it creates a two-page `spread.pdf`. Use a dedicated output directory because these local output names are reused. Check both final page images against the pinned text, including accents and punctuation. The command reports the native effective PPI so an operator can assess lettering at print size.

For a complete local proof, run `npx tsx scripts/render-premium-edition.ts <manifest.json> <asset-dir> <new-output-dir> [specification-qr.png]`. Place local copies of cover and page artwork and any opening motif in the asset directory using their content-addressed file names. The command checks each file against its manifest digest and byte count, then uses the paid-proof renderer to write `interior.pdf` and `cover.pdf`. It uses the packaged publication QR unless a local PNG is supplied, and loads the frozen back-cover logo from its packaged assets. The usual Chromium, Poppler and sRGB profile dependencies apply. PDF quality issues are reported in the command output and set a nonzero exit status.

## Operator recovery and correction

Call `POST /internal/premium/runs/{runId}/resume` with `{ "storyId": "…" }` through authenticated SGW access. It resumes an eligible failed or blocked run, or a run whose recorded Workflows execution has failed. Active work returns its current run identity. Concurrent retry calls converge at the workflow claim, which checks the same prior status and update timestamp. The original acceptance, debit, revision and validated checkpoints are retained.

Call `POST /internal/premium/stories/{storyId}/corrections` with the current `expectedRevision`, a new UUID `correctionId` and one `spreadId` (such as `spread-3`). Provide `leftText`, `rightText` or `artworkInstructions` as needed. To switch a pair to `right_only`, explicitly provide that layout, empty `leftText` and the new `rightText`. To restore `both_pages`, provide the new left line. A change to embedded text generates and verifies a replacement spread in the same layout. For older editions with text overlays, text-only corrections reuse the existing artwork. Artwork corrections generate and verify a new master and both derivatives. The request may be retried with the same body and correction ID. A stale expected revision must be reviewed before another attempt. The returned revision includes `previousRevision` in its manifest so staff can explicitly rebind a held paid order through the existing revise-proof workflow.

The owner reader calls `POST /internal/premium/stories/{storyId}/text-edits` through the authenticated WebApp. It supplies the verified `ownerId`, the current `expectedRevision`, a new UUID `correctionId`, `pageNumber` and the complete replacement `text`. Owners can change their dedication, synopsis, dedicated typeset text and legacy narrative overlays. The renderer checks the text area before publication and refreshes the edited typeset or opening preview. Synopsis changes appear on the interior page and on the back cover of editions with a synopsis overlay. The story row and immutable revision pointer advance together, and the request can be retried with the same body and correction ID. Manual edits reuse the existing artwork and consume zero credits.

### Draft retention

After a premium run reaches `completed` or `cancelled`, the worker makes a best-effort pass over the run's `review/` objects. It checks execution identity again after listing and deletes only the exact generations of matching `.draft.jpg` objects. This cleanup uses existing bucket permissions to list and delete objects. Failed and blocked runs retain their drafts for same-run recovery. Published assets, paid-order pins and stage checkpoints remain available.

As a bucket backstop, use a seven-day Cloud Storage lifecycle delete rule with `age: 7` and `matchesSuffix: [".draft.jpg"]` on the dedicated premium bucket. Cloud Storage takes a literal suffix. This rule covers drafts left by interrupted runs, abandoned corrections and transient cleanup failures. Same-run recovery can generate fresh artwork if its draft has expired. Existing soft-delete and versioning policies still apply. [Cloud Storage lifecycle conditions](https://docs.cloud.google.com/storage/docs/lifecycle#lifecycle_conditions)

## Online editions and owner edits

Generation publishes the digital edition without creating PDFs. Owner edits send illustration instructions to `/internal/premium/stories/{storyId}/corrections/prepare`. The Web App applies the pinned manifest and records any image-edit debit in one database transaction. Staff can use the direct corrections endpoint for an illustration or manuscript change. A new revision requires its own audiobook and any previously accepted self-print request retains its original edition pin. A paid physical order retains its edition until staff explicitly rebinds a held order to a reviewed revision. The premium copy endpoint gives each owner duplicate its own story and immutable image paths. Only self-print and physical proof requests enter the PDF renderer.

## Imported reading proofs

An imported reading proof uses the version 1 `readingProof` manifest field. The generation, byte length and SHA-256 of its source-resolution report, interior PDF and casewrap PDF are pinned inside the same story’s import revision. Native pixel dimensions and calculated effective PPI are retained at their measured values. The lower-density exception applies only to imported reading proofs. Customer print and physical-order rendering reject these editions. Staff RGB exports of the original import use the exact reviewed PDFs. Later edits retain the proof restriction and staff exports render the edited revision.
